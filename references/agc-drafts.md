# AGC 填写、上传与自检

## 更新已有版本

1. 确认 Android/HarmonyOS 平台、真实产品名称、appId/projectId、版本页和当前审核状态。对审核报告先检查最终现有包是否已修复，再决定改代码；不能看到旧报告就重复返工。
2. 按当前功能逐项检查介绍、分类、更新内容、图标、截图、隐私政策/权限、标签、审核备注。分类按本次审核具体要求和真实用途，不能把生活/效率分类固化给所有应用。
3. 更新说明只写本次实际变化及用户可见路径；不要声称已通过实测、修复所有问题或虚构“设置→反馈”入口。审核对照、设备限制、测试步骤写审核信息，不塞入用户介绍。
4. 本地签名包用中文名上传，核对浏览器文件选择的 basename 和远端行名均正确。工具不支持中文路径时可以用隔离的英文父目录，里面仍保留中文文件名；不得把 kejian、keshi 等 ASCII 临时名作为最终远端交付。不要为改名字改包体、包名或签名。
5. 等待表格数据加载，再按 filename + versionName/code 查已存在记录。异步上传弹“解析失败”并不总意味着最终入库失败：先查软件包管理、合法性和详情；先等有界处理，再决定是否重试，避免堆出重复包。持续失败时记录实际错误详情，不能将所有解析失败都归咎未签名。
6. 同版本有多行时，选择正确文件名/版本且 **radio 可用、合法性已达标** 的行；处理中的第一行可能禁用。记录所选行，再确认版本页真实显示的新包，不能只看弹窗关闭。
7. 点击保存草稿，核对成功提示，重新打开该版本确认选中包、文案和权限说明均持久化。未得到授权不点击提交审核/上架。后台已撤销版本能否复用，按实际界面处理。
8. 启动可用的平台自检，读取报告，保存任务 ID 和结果。HarmonyOS NEXT 原生包选择满足其 compatibleSdkVersion 的环境；APK 在 HarmonyOS 2/3/4 上启动失败不能用“只能支持鸿蒙5”解释，须查 Android SDK/WebView/ABI/启动异常。

## 截图与图标

- 按当前后台字段的张数、尺寸、比例、单文件上限和格式处理，不能将某个入口的 3–5 张/2MB 或另一个入口的 5MB 混用。1080×1920 是常用交付规格，不是所有入口的唯一标准。
- 用户要求艺术宣传版时，沿用已确认的主题、版式和层次，替换为最新真实运行界面。不同 App 有不同主题；优先展示核心功能、编辑、记录、使用习惯等完整路径，不是五张相同首页。
- AI 可生成装饰背景，不能虚构产品 UI、拍照结果、宠物状态或功能。保留原版和新版，分别输出宣传版与合规格商店版；检查裁切、可读文字、手机框对齐、状态栏、按钮、敏感信息和排序。
- 领宠案例用户指定小柴犬，不能继续用不满意的狐狸。相同品牌 Android/HarmonyOS 图标保持统一，真实安装图标、后台图标和宣传图准确一致；不把应用不具有的另一平台界面当真实截图。

## 浏览器自动化可靠性

DOM/实际 UI 是字段依据，不猜选项和状态。选择器限定当前应用和可见弹层；异步表格和 iframe 加载后再操作。保存成功必须有当前页面证据并重开核对。下载/上传的文件大小只是线索，不直接推定包缺资源或故障。登录失效时请用户在实际新开的窗口完成登录，不索要密码验证码。
