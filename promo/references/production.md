# 真实截图、版本替换与交付

## 真实页面截图

能使用真机截图时可直接采用；网页是 App 的真实模拟时，也可以用 Chrome 截图。先检查路由、界面主题、安全区和设备比例与目标版本是否一致。

使用独立浏览器上下文或临时配置：

- 查当前 App 的 localStorage 键和状态结构，再注入演示数据。不要复制其他产品的键、路由或字段。
- 演示订单、记录或自定义内容要合理，金额与名称应在相关页之间一致。涉及估算或容易被理解为真实成绩的数据，在图册中给出简短说明。
- 等待字体、可见图片解码和页面稳定。不要无限等待还未滚动到的懒加载图片。
- 动效在合适时刻暂停后截图。例如弹幕仍应处于自然可见的位置，不把动画直接归零导致整个背景消失。
- 深色界面的状态栏用合适的浅色文字；浅色界面反之。状态栏、摄像孔与底部手势条只处理一次。
- 截图不包含网页调试面板、浏览器工具栏或桌面预览控制区。
- 如果启动占位容器的临时内联样式造成多余边距，先确认它不是目标界面设计，再在截图环境中处理。不要为修截图擅自更改正式布局或取消安全区。

分享卡、凭证、海报等功能，应在界面中实际生成后读取结果或截取元素。这样能保留真实餐品、价格、图标和文案，避免宣传图与软件结果不一致。

## 精确排版与导出

可用 HTML/CSS 制作每页定宽高的容器，在项目已有的 Puppeteer、Playwright 或浏览器工具中导出。不要把整套页面 UI 再用 AI 图片工具生成一遍。

- 使用可读的文字元素排标题和说明；截图作为图片放入手机屏幕容器。
- 屏幕与原截图保持相同比例。例如 390×844 截图应使用 `aspect-ratio: 390 / 844`，不能为了贴合不准确的手机壳而拉伸。
- 手机外框尺寸应由屏幕与边框共同计算。逐页检查实际下缘，不能让页脚盖住手机底部。故意裁切需要明显的构图理由，不能看起来像排版错误。
- 外部字体、图片要本地化或嵌入源文件，以便离线预览和跨电脑使用；字体需具备相应使用权限。
- 高分辨率渲染后可以导出较小 JPG，既清晰又方便发布。例如 2160×2880 原图缩至 1080×1440，JPG 质量 92–95 可作为起点，再看细字与照片效果。
- 保留源文件、页码与资产映射。避免只保存无法继续修改的一组扁平图片。
- 如需 PDF，设置打印页尺寸与图片比例一致，关闭页眉页脚并保留背景；再次渲染检查每一页，没有多出的空页或字体替换。
- 总览用于选图，不能代替每页大图检查。预览页应能放大查看，并按实际交付文件引用图片。

## 用已发布版本的旧图片

要恢复旧图片时，按可靠程度优先使用目标版本的原截图、对应构建资源、上传包里的资源。文件名与修改时间只能辅助判断，不能单独证明已上架。

如果用户确认要的是某个版本的完整页面，应运行该版本或使用其真机截图。如果用户只要求沿用当前排版并换回旧图片：

1. 新建版本目录，复制排版与必要截图，保留原件。
2. 建立当前图片与旧图片的映射。按店铺 ID、菜品 ID、名称以及旧版本数据核对，不能凭文件名相似随意替换。
3. 可以在独立截图浏览器拦截图片请求，使用旧资源响应；或使用独立构建副本。处理所有可见图，包括首页封面、店内头图、菜单、订单缩略图和自定义示例。
4. 自定义上传产生的 data URL 不经过网络请求拦截，应在演示环境上传对应旧素材。
5. 只重新生成受影响截图，再用原版式导出。无图片变动的页可保留原文件。
6. 写简短版本说明，准确区分「完整旧版截图」与「当前布局配旧版图片」。缺少旧资源时说明缺失，不默默混入新图片。

鸿蒙 `.app` 包通常可以按 ZIP 读取，内部 HAP 再读取其网页资源，例如 `resources/rawfile/`。只提取所需网页与公开素材，跳过证书、Profile、密钥等无关文件。归档结构以实际包为准。每个输出路径规范化后必须位于指定提取目录内，防止路径穿越。Windows 文件操作使用同一 PowerShell 会话的原生路径 API 与命令。

本次案例使用图片更新前的 1.0.4 包提取旧店铺和餐品素材，在独立截图环境替换图片，分别保留两套桌面图册与两份 Canva 设计。其他 App 应重新确认包名、版本和素材映射，不复用这些具体路径。

## Canva 可选交付

先发现当前可用的 Canva 工具并读它的实际 schema，不假定所有会话都有同样功能。

- 精确排版完成后，可导入保留文字与图片的 PDF，继续编辑宣传标题和说明。不要声称导入后截图中的每个控件都独立可编辑。
- 若工具 schema 明确接受 `design_file` 本地文件参数，传入成品的绝对路径；不要把本地路径塞进公共 URL 参数。
- 需要上传时，按工具返回的协议发送文件字节。一次性上传 URL 只使用一次，不能反复重试或在用户输出中暴露上传令牌。仅把返回的合法资源标识交给后续工具。
- 对已有设计的修改遵循当前工具的权限与事务要求。保留原版并另建变体时，不覆盖原设计。
- 确认页数、比例、文字和缩略图；需要时看导入后的实际画面。PDF 导入可能拆分或分组元素、改变字体，不能保证与本地 PNG 完全一致。
- 提供清晰命名的编辑链接。本地逐页检查过的发布图片仍要交付，方便用户直接发布。
- 连接、认证或能力不可用时，完成本地图片、预览、源文件与 PDF；简短说明 Canva 部分的实际限制。不要为了获得编辑链接擅自把本地文件公开托管。

## 输出目录

按用户需要选择文件，不必每次全部生成：

```text
产品名-宣传图册-版本或日期/
  社交发布JPG/
  高清PNG/
  图册总览.png
  预览.html
  可编辑排版源文件.html
  产品名-宣传图册.pdf
  发布文案与版本说明.md
  Canva编辑链接.url
```

跨电脑交付源文件时检查相对引用能否工作。导出 ZIP 时只打包需要发布的图片或完整交付目录，不夹带依赖目录、浏览器配置、个人数据或签名材料。
